# Cycle Master — 故事内容格式规范 v1.0

> **用途**：定义故事剧本在程序中的存储格式和编写规范。故事完成后，按此格式填入对应的 JSON 文件，后端导入 SQLite 数据库，前端即可读取运行。

## 一、总体约定

### 1.1 数据格式

所有故事数据以 **JSON** 格式组织，分为若干独立文件。每个文件对应一个逻辑单元（节点定义、道具定义、NPC 定义等）。

### 1.2 文件组织

```
story_data/           # 故事数据目录（待创建）
├── 00_meta.json                  # 剧本元信息
├── 01_flags.json                 # 全局标记（Flag）定义
├── 02_items.json                 # 道具（Item）定义
├── 03_npcs.json                  # NPC 定义
├── 04_player_attributes.json     # 玩家属性定义
├── 05_nodes/                     # 节点定义（一个文件一个节点）
│   ├── A_起点.json
│   ├── B_出租屋.json
│   ├── C_华林寺.json
│   ├── D_上下九.json
│   ├── E_八棺之地.json
│   ├── F_沙面珠江.json
│   ├── G_陈家祠.json
│   ├── H_康王路.json
│   ├── J_地宫暗道.json
│   ├── K_龙脉裂隙.json
│   ├── S1_B1卖场入口.json
│   ├── S2_德星路神龛.json
│   └── ...                       # S3~S20
└── 06_choices/                   # 每个节点的选择分支（独立管理）
    ├── A_choices.json
    ├── B_choices.json
    └── ...
```

### 1.3 命名规范

| 对象 | ID 格式 | 示例 |
|------|---------|------|
| 主节点 | `A`~`H` | `"A"`, `"E"` |
| 特殊节点 | `J`, `K` | `"J"`, `"K"` |
| 子节点 | `S1`~`S20` | `"S1"`, `"S15"` |
| 普通节点 | `N_xxx` | `"N_market_stall"` |
| 道具 | `item_xxx` | `"item_amulet"`, `"item_beads"` |
| Flag | `snake_case` | `"know_secret_tunnel"`, `"helped_ergou"` |
| Choice | `{from_node}_choice_{序号}` | `"A_choice_01"` |
| NPC | `npc_xxx` | `"npc_zhang_tianmin"` |

### 1.4 内容中的特殊语法

正文（`content` 字段）支持 Markdown 子集：

| 语法 | 用途 |
|------|------|
| `**粗体**` | 强调关键词 |
| `*斜体*` | 心理活动、轻声 |
| `~~删除线~~` | （暂未使用） |
| `---` | 场景分隔 |
| `> 引用` | 回忆/幻觉中的话语 |

**不支持的 Markdown**：图片、表格、HTML、代码块（如有需要后续扩展）。

### 1.5 模板条件块语法

正文（`content` 和 `cycle_variants` 中）支持简单的条件块，用于根据游戏状态动态显示不同文本：

| 语法 | 用途 |
|------|------|
| `{{#if 条件}}文本{{/if}}` | 条件满足时显示文本 |
| `{{#if 条件}}文本A{{else}}文本B{{/if}}` | 条件满足显示A，否则显示B |

**条件块中支持的条件表达式**：

```yaml
has_flag:xxx        # 是否存在某flag
has_item:xxx        # 背包中是否持有某道具
attr:xxx>=N         # 属性比较（支持 >=, <=, >, <, ==, !=）
cycle>=N            # 完整循环次数
half_cycle>=N       # 半循环次数
not:条件             # 取反
and:条件1,条件2      # 全部满足
or:条件1,条件2       # 满足其一
```

**示例**：

```
{{#if has_flag:timeline_mapped}}你想起在陈家祠看到的县志——你知道现在可以选择穿越到哪个精确时间点。{{/if}}

{{#if has_item:item_amulet}}你的手指无意识地碰了碰口袋里的护身符。它还在。{{else}}你的口袋是空的。但你总觉得——本来应该有什么东西在那里的。{{/if}}

{{#if and:has_flag:taoist_chant,attr:courage>=5}}你默念口诀，脚下的震动停止了。龙脉听到了你。{{/if}}
```

**注意**：条件块不可嵌套。引擎渲染时先解析条件块，再解析 `{{变量}}` 替换。

## 二、节点（StoryNode）格式规范

### 2.1 完整 Schema

```jsonc
{
  // ========== 基础标识 ==========
  "id": "A",                           // 唯一标识，见命名规范
  "name": "荔湾广场正门",               // 显示名称
  "position": 0.0,                     // 环面位置 (0-200)，主节点固定：
                                        //   A=0, B=25, C=50, D=75,
                                        //   E=100, F=125, G=150, H=175
                                        //   特殊节点 J/K 用 -1
                                        //   子节点用它最靠近的主节点的 position
  "node_type": "main",                 // "main" | "normal" | "special_shortcut" | "special_warp"

  // ========== 故事内容 ==========
  "time_label": "第一天·傍晚 18:30",    // 时间标签（前端显示）
  "content": "正文内容，见 2.2 节",      // 正文，Markdown 格式，见下方规范
  "speaker": null,                     // 说话人（null=旁白, NPC的ID=具体人物）
  "background": "/assets/bg/square.jpg", // 背景图路径（暂可留空）

  // ========== 性别差异 ==========
  "gender_variant": {                    // 性别差异内容（可选，无差异时省略）
    "male": "男性主角专属描述文本",
    "female": "女性主角专属描述文本"
  },

  // ========== 循环相关 ==========
  "cycle_variants": {                  // 不同循环轮次的内容变体
                                        // key 为 "cycle_N" 或 "cycle_N+"
    "cycle_1": "第1次循环的特殊文本（覆盖 content）",
    "cycle_3+": "第3次及以后的文本",
    "cycle_5": "第5次循环的精确文本"
  },
  "cycle_variants_note": "cycle_N 精确匹配第N次；cycle_N+ 从第N次开始生效；没匹配到的回退到 content 默认值",

  // ========== 场景属性 ==========
  "color_palette": "暗红+金色",         // 色调参考
  "atmosphere": ["暮色", "既视感", "轮回将至"],  // 氛围关键词
  "sensory": "暖风、远处人声、复古的黄昏光",      // 感官描述（给文案的美术参考，游戏不直接使用）

  // ========== 子节点关联 ==========
  "linked_sub_nodes": [                 // 本节点关联的子节点（可选探索点）
    { "node_id": "S1", "trigger": "A节点选择'先在周边转转'后可选进入" },
    { "node_id": "S2", "trigger": "步行前往B节点时选择'走小巷抄近路'" }
  ]
}
```

### 2.2 正文（content）编写规范

```markdown
# 正文模板示例（A节点）

夕阳将荔湾广场圆弧形穹顶染成暗红色。正门上方的"荔湾广场"四个金色大字在暮色中闪着廉价的光泽。

你站在广场B1入口前，手机上是租房APP的确认信息——德星路502房，月租600元。屏幕右上角的时间停在**2018年7月15日，傍晚18:30**。

_（这个点搬家的人应该不多。先去办入住吧。）_

广场门口一对铜狮在夕阳下拉出长长的影子。你注意到它们面朝广场内部——而不是朝外。很奇怪。一般的石狮子不都是朝外的吗？

---

门口零星站着几个人：发传单的小哥在刷手机，推着婴儿车的老人慢悠悠地经过，B1入口往下走的扶梯上站着几个逛完珠宝市场的顾客。

傍晚的闷热空气中混着远处卤味铺飘来的八角香味。一切都再正常不过——正常的夏日黄昏，正常的荔湾老城区，正常得让人想打哈欠。

只有那对铜狮，在阳光下沉默地盯着广场的方向，像是看管着什么东西。
```

**编写规则：**

1. **段落间用空行分隔**：前端会根据空行分段，控制打字机效果的节奏
2. **`_斜体_`用于心理活动**：前端用斜体样式呈现
3. **`---`用于场景转换**：前端暂停打字机效果，短暂停顿后再继续
4. **单段不宜超过 150 字**：保证阅读节奏
5. **speaker 非 null 时，正文是对话内容**：前端自动加上对话气泡样式
6. **旁白（speaker=null）用描述性文字**：前端用正常叙事样式

### 2.3 对话格式

当 `speaker` 不为 null 时，正文是 NPC 的台词：

```jsonc
{
  "speaker": "npc_zhang_tianmin",
  "content": "\"你是新来的。\"他抬起头，眼眶下有很重的黑眼圈。\"第几天？不用回答——我知道。第一天。你的眼神还没有那种东西。\""
}
```

旁白和对话混合时，用 `---` 分隔不同段落，切换 `speaker` 需要分到不同的节点帧。

### 2.4 循环变体（cycle_variants）完整示例

```jsonc
{
  "content": "你站在荔湾广场正门前，手机上的日期是2018年7月15日。",
  "cycle_variants": {
    "cycle_1": "你第一次站在这扇门前。暮夏的闷热让你出了一身汗。\n\n手机上是租房APP的确认信息——德星路502房，月租600。你心想：_（便宜是便宜，希望不要太破。）_",
    "cycle_2": "熟悉的感觉涌上心头。你站在同样的位置，面对同样的铜狮，手机上的日期还是7月15日。\n\n_（这不对。）_\n\n你的手无意识地伸进口袋——护身符还在。你不记得为什么它会在你的口袋里，但它就是在那。",
    "cycle_3+": "已经是第{{cycle_count}}次了。你不再感到惊讶，而是开始观察。\n\n铜狮的朝向、招牌上的'广'字、台阶砖缝里那枚怎么也撬不出来的铜钱——它们每轮都一样，但你知道它们不是。"
  }
}
```

**模板变量（`{{...}}`）**：引擎渲染时将 `{{cycle_count}}` 替换为实际值。可用变量：`{{cycle_count}}`、`{{half_cycle_count}}`、`{{attr:sanity}}`、`{{attr:courage}}` 等。

## 三、选择分支（Choice）格式规范

### 3.1 完整 Schema

```jsonc
{
  "id": "A_choice_01",                 // 唯一标识
  "from_node_id": "A",                 // 来源节点
  "text": "直接进入广场办理入住",       // 选项文本（15字以内）
  "short_text": "办理入住",            // 简版文本（可选，用于紧凑UI）
  "next_node_id": "B",                 // 目标节点
  "condition": null,                   // 条件表达式（null = 始终可选）
  "effects": [                         // 选择触发的效果列表
    {
      "type": "set_flag",
      "target": "started_standard_path",
      "value": true
    }
  ],
  "priority": 1,                       // 排序优先级（数字越小越靠前，默认 99）
  "hint": null,                        // 条件不满足时的提示文字
  "is_hidden_when_locked": false,      // 条件不满足时是否完全隐藏（默认 false = 置灰显示）
  "transition_text": null              // 选择后、跳转前显示的过渡文本（可选，支持 Markdown）。
                                        // 用于"留在当前节点"的选项（next_node_id == from_node_id）
                                        // 提供叙述反馈；也可用于跨节点过渡动画的文字描述
}
```

### 3.2 条件表达式详细语法

```yaml
# ──── 基本条件 ────
has_item:道具ID              # 背包中是否持有某道具
flag:标记名=值               # 标记是否等于指定值（值可以是 true/false/数字/字符串）
attr:属性名>=值              # 属性比较（支持 >=, <=, >, <, ==, !=）
cycle>=N                    # 完整循环次数
half_cycle>=N               # 半循环次数
at_node:节点ID               # 当前是否在某节点

# ──── 组合条件 ────
not:子条件                   # 取反
and:条件1,条件2,...          # 全部满足
or:条件1,条件2,...           # 满足其一

# ──── 嵌套示例 ────
and:has_item:item_beads,or:attr:courage>=8,cycle>=3
# 解析：持有念珠 且 (勇气≥8 或 循环≥3)
```

### 3.3 效果（Effect）类型完整列表

```yaml
# ──── 道具类 ────
add_item:道具ID              # 添加道具到背包（value=1或数量）
remove_item:道具ID           # 移除道具（value=1或数量）

# ──── 标记类 ────
set_flag:标记名              # 设置标记（value=标记值，通常为true）
remove_flag:标记名           # 移除标记（value 忽略）
toggle_flag:标记名           # 切换标记布尔值

# ──── 属性类 ────
heal:属性名                  # 恢复属性（value=恢复量）
damage:属性名                # 扣除属性（value=扣除量）
set_attr:属性名              # 直接设置属性值（value=新值）

# ──── 持久化类 ────
leave_item:道具ID            # 在当前节点遗留道具（value=道具ID）
leave_danger:危险ID          # 在当前节点遗留危险（value=危险ID）
remove_persistent_item:道具ID # 移除当前节点的某个遗留道具

# ──── 特殊类 ────
trigger_cutscene:过场ID     # 触发特殊过场动画/事件
set_san_max:值              # 修改 san 值上限（value=变化量，如 -1）
```

### 3.4 Choice 完整示例

```jsonc
// A节点 → 三条选择
[
  // 选择①：标准开局，始终可选
  {
    "id": "A_choice_01",
    "from_node_id": "A",
    "text": "直接进入广场办理入住",
    "short_text": "办理入住",
    "next_node_id": "B",
    "condition": null,
    "effects": [
      { "type": "set_flag", "target": "started_standard_path", "value": true }
    ],
    "priority": 1
  },

  // 选择②：周边探索，始终可选
  {
    "id": "A_choice_02",
    "from_node_id": "A",
    "text": "先在周边转转，熟悉环境",
    "short_text": "周边转转",
    "next_node_id": "A",               // 留在A但触发探索子事件
    "condition": null,
    "effects": [
      { "type": "set_flag", "target": "exploring_surroundings", "value": true }
    ],
    "priority": 2,
    "hint": "可能会发现一些有用的东西"
  },

  // 选择③：第2次循环起，跨面道具出现在口袋时触发
  {
    "id": "A_choice_03",
    "from_node_id": "A",
    "text": "检查口袋里的护身符",
    "short_text": "检查护身符",
    "next_node_id": "A",               // 留在A但触发检查护身符的叙述

    "effects": [
      { "type": "set_flag", "target": "checked_pocket_item", "value": true },
      { "type": "heal", "target": "sanity", "value": 3 }
    ],
    "priority": 0,                      // 最高优先级，有道具时排最前
    "is_hidden_when_locked": true       // 无道具时完全不显示
  },

  // 选择④：仔细查看租房信息（第2轮+，触发既视感）
  {
    "id": "A_choice_04",
    "from_node_id": "A",
    "text": "仔细查看租房信息",
    "short_text": "查看信息",
    "next_node_id": "A",
    "condition": "cycle>=2",
    "effects": [
      { "type": "set_flag", "target": "deja_vu_triggered", "value": true }
    ],
    "priority": 3
  }
]
```

## 四、道具（Item）格式规范

### 4.1 完整 Schema

```jsonc
{
  "id": "item_amulet",                  // 唯一标识
  "name": "阿六的护身符",               // 显示名称
  "category": "npc_gift",              // 分类：npc_gift | scene_discovery | sub_node | eternal | hidden
  "description": "巴掌大的桃木牌...",   // 物品描述（背包内查看时显示）
  "flavor_text": "木牌边缘因常年被握在手中而磨得光滑发亮。", // 风味文字（可选，初次获得时显示）
  "cross_surface": true,               // 是否 A↔E 跨面共享
  "consumable": false,                 // 是否为消耗品
  "stackable": false,                  // 是否可堆叠（同ID可持有多个）
  "stack_max": 1,                      // 堆叠上限（stackable=false 时默认为1，特殊道具如破布设为100）

  // 效果（持有时的被动效果和主动使用效果）
  "passive_effects": [                 // 持有即生效的被动效果
    {
      "type": "san_drain_reduce",      // san值消耗减缓
      "value": 0.15                    // 减缓15%
    }
  ],
  "active_effects": [],                // 主动使用时的效果（消耗品才有）
  "use_prompt": null,                  // 主动使用时弹出的确认文案（消耗品才有）
  "use_condition": null,              // 使用条件（null = 始终可用）
  "can_discard": false,               // 是否可丢弃

  // 与其他节点的互动
  "k_node_use": "sacrifice_material",  // K节点用途：sacrifice_material | key | none
  "k_node_value": 1,                   // K节点献祭时的价值（补阵恢复量，1=修复一个光团的基础量）

  // 磨损/消耗机制（如有）
  "wear_mechanism": {                  // 可选，无则省略
    "max_uses": 8,
    "wear_trigger": "cross_surface_transfer",  // 触发磨损的条件
    "on_depleted": "destroy"           // 耗尽后的行为: destroy | transform:新道具ID
  }
}
```

## 九、数据库导入映射

### 9.1 JSON → SQL 转换规则

JSON 文件通过后端导入脚本（`backend/import_story.py`）批量导入 SQLite：

| JSON 字段 | SQL 表 | SQL 列 | 转换 |
|-----------|--------|--------|------|
| 节点的 `id`~`background` | `story_nodes` | 对应列 | 直接映射 |
| 节点的 `cycle_variants` | `story_nodes` | `cycle_variants_json` | 序列化为 JSON 字符串 |
| 节点的 `color_palette` 等 | `story_nodes` | `metadata_json` | 合并到 metadata JSON 列 |
| Choice 全部字段 | `choices` | 对应列 | `effects` 序列化为 JSON 字符串 |
| Item 全部字段 | `items` | 对应列 | `passive_effects` 等序列化为 JSON 字符串 |
| Flag 全部字段 | `flags_def` | 对应列 | 直接映射 |
| NPC 全部字段 | `npcs` | 对应列 | `appears_at_nodes` 等序列化为 JSON 字符串 |

### 9.2 扩展的 SQL 表

原技术方案中的 `story_nodes` 表需要新增以下列以支持故事内容：


## 十、导入脚本接口约定

后端 `import_story.py` 将读取上述 JSON 文件并写入 SQLite。其接口设计：

```python
# backend/import_story.py (伪代码)

def import_all(data_dir: str = "design_docs/story_data"):
    """批量导入所有故事数据"""
    # 1. 清空现有故事数据（保留存档数据）
    # 2. 导入 00_meta.json → 验证版本
    # 3. 导入 01_flags.json → flags_def 表
    # 4. 导入 02_items.json → items 表
    # 5. 导入 03_npcs.json → npcs 表
    # 6. 导入 04_player_attributes.json → 校验属性定义
    # 7. 遍历 05_nodes/*.json → story_nodes 表
    # 8. 遍历 06_choices/*.json → choices 表
    # 9. 校验外键完整性（choice 的 next_node_id 必须存在于 story_nodes）
    # 10. 校验条件表达式语法（condition 字段语法检查）
    pass
```

**校验规则：**
- 所有 `next_node_id` 必须指向已定义的节点
- 所有 `from_node_id` 必须指向已定义的节点
- Choice 的 `effects` 中引用的道具/flag/属性必须已定义
- `cycle_variants` 的 key 必须匹配 `cycle_N` 或 `cycle_N+` 格式
- `cross_surface=true` 的道具至少在一个 A 或 E 节点的 Choice 中被引用

## 十六、快速参考卡

### 条件表达式速查

| 表达式 | 含义 |
|--------|------|
| `null` | 始终可用 |
| `has_item:item_xxx` | 持有道具 |
| `has_flag:xxx` | flag 为 true |
| `flag:xxx=value` | flag 等于指定值 |
| `attr:courage>=5` | 勇气≥5 |
| `cycle>=3` | 第3次以上循环 |
| `half_cycle>=1` | 至少触发过1次半循环 |
| `at_node:E` | 当前在E节点 |
| `not:xxx` | 取反 |
| `and:a,b` | 两个都满足 |
| `or:a,b` | 满足任意一个 |

### 效果类型速查

| 类型 | target | value | 说明 |
|------|--------|-------|------|
| `add_item` | 道具ID | 数量 | 获得道具 |
| `remove_item` | 道具ID | 数量 | 移除道具 |
| `set_flag` | flag名 | true/false | 设置标记 |
| `remove_flag` | flag名 | — | 移除标记 |
| `heal` | 属性名 | 恢复量 | 恢复属性 |
| `damage` | 属性名 | 扣除量 | 扣除属性 |
| `leave_item` | 道具ID | 道具ID | 遗留道具 |
| `leave_danger` | 危险ID | 危险ID | 遗留危险 |

### 道具分类速查

| 分类 | 跨循环保留 | 示例 |
|------|-----------|------|
| `npc_gift` | 是 | `item_amulet` |
| `scene_discovery` | 是 | `item_qing_coin` |
| `sub_node` | 是 | `item_jade_pendant` |
| `eternal` | 是（不可丢弃） | `item_rent_key` |
| `hidden` | 是 | `item_denim_rag` |

### 节点类型速查

| 类型 | position | 特点 |
|------|----------|------|
| `main` | 0/25/50/75/100/125/150/175 | 骨架节点，必经过 |
| `normal` | 可变 | 普通剧情/子节点 |
| `special_shortcut` | -1 | J节点，条件捷径 |
| `special_warp` | -1 | K节点，条件跃迁 |
