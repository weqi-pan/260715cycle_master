# Cycle Master 故事内容格式规范 v2

> v2 的目标是让剧情数据明确描述展示顺序，前端只负责播放，不再从多个字符串字段推断流程。

## 1. 文件组织

每个节点一个 JSON 文件，节点入场内容和该节点的全部选项共置：

```text
data/story_data_v2/
├── manifest.json
├── story-node-v2.schema.json
└── nodes/
    ├── A_起点.json
    ├── B_出租屋.json
    └── ...
```

`data/story_data_v2` 是运行时唯一剧情数据源；SQLite 只保存玩家存档。

## 2. 顶层字段

| 字段 | 说明 |
|---|---|
| `schema_version` | 固定为 2 |
| `id` | 节点稳定 ID |
| `meta` | 名称、类型、位置、时间和父节点 |
| `scene` | 背景、色板、环境音和氛围 |
| `entry_sequences` | 进入节点时按条件选择的内容序列 |
| `choices` | 该节点的选择、结果内容、效果和下一步 |
| `routing` | 跨面、J 捷径、K 跃迁配置 |
| `authoring` | 编剧和编辑器使用的辅助元数据 |

## 3. 内容块

### 3.1 narration

正文、场景描述、心理活动和选择结果旁白。显示为一段叙事文本并使用打字机效果。

```json
{
  "id": "A.entry.default.narration.01",
  "type": "narration",
  "text": "夕阳从荔湾广场的玻璃穹顶上滑落。"
}
```

### 3.2 dialogue

角色台词。`speaker_id` 必填：`player` 固定显示在右侧，其他角色固定显示在左侧。

```json
{
  "id": "C.entry.dialogue.01",
  "type": "dialogue",
  "speaker_id": "npc_yan_yan",
  "text": "你也来逛华林寺？"
}
```

禁止按数组奇偶、性别或临时 CSS 推断左右位置。

对话块还必须遵守：

- `text` 只包含人物实际说出口的内容，不保留外层直引号；
- “她说”“他问”“压低声音”“合上笔记本”等动作与说话提示必须拆成相邻的 `narration`；
- 对话内需要强调或转述时使用单引号/书名号，避免与迁移期直接引语边界混淆；
- schema 会拒绝仍含 `"`、`“`、`”` 的对话块。

例如：

```json
[
  {
    "id": "C.choice.exchange.result.01.dialogue",
    "type": "dialogue",
    "speaker_id": "npc_yan_yan",
    "text": "你知道吗，荔湾广场那个地方——"
  },
  {
    "id": "C.choice.exchange.result.02.narration",
    "type": "narration",
    "text": "她压低声音，"
  },
  {
    "id": "C.choice.exchange.result.03.dialogue",
    "type": "dialogue",
    "speaker_id": "npc_yan_yan",
    "text": "我查过了。1993年施工的时候……"
  }
]
```

### 3.3 system

获得道具、属性变化和线索更新等系统提示。效果本身仍写在 `effects` 中。

```json
{
  "id": "C.choice.sutra.system.01",
  "type": "system",
  "text": "获得道具：慧觉经文残片"
}
```

## 4. 条件内容

文本中禁止使用：

```text
{{#if ...}}
{{else}}
{{/if}}
```

条件应放在 `entry_sequence.when` 或 `block.when`：

```json
{
  "id": "A.choice.coin.result.narration.02",
  "type": "narration",
  "when": "cycle>=2",
  "text": "铜钱还在砖缝里。和你上次取走的那枚一模一样。"
}
```

允许使用简单变量插值，例如 `{{cycle_count}}`。变量解析由后端完成，前端不执行剧情模板。

当前白名单变量只有 `cycle_count` 与 `half_cycle_count`；未知变量在数据校验阶段直接报错。

## 5. 入场序列

引擎从条件满足的序列中选取 priority 最高者：

```json
{
  "id": "A.entry.cycle_3_plus",
  "when": "cycle>=3",
  "priority": 30,
  "blocks": []
}
```

每个节点必须有 `when: null` 的默认序列。

## 6. 选择

```json
{
  "id": "A_choice_02",
  "label": "观察铜狮底座",
  "short_label": "观察铜狮",
  "condition": null,
  "locked_visibility": "show",
  "repeat_policy": "once_per_visit",
  "priority": 2,
  "hint": null,
  "result_blocks": [],
  "effects": [],
  "next": {
    "node_id": "A",
    "mode": "stay"
  }
}
```

### 6.1 repeat_policy

| 值 | 语义 |
|---|---|
| `always` | 可无限重复 |
| `once_per_visit` | 本次进入节点期间只能选择一次 |
| `once_per_cycle` | 每轮循环一次 |
| `once_ever` | 整个存档一次 |

### 6.2 locked_visibility

| 值 | 语义 |
|---|---|
| `show` | 条件不满足时置灰并显示 hint/reason |
| `hide` | 条件不满足时完全隐藏 |

### 6.3 next.mode

| 值 | 语义 |
|---|---|
| `stay` | 节点内互动，结果播放后刷新本节点选项 |
| `travel` | 普通跨节点移动 |
| `shortcut` | 经过 J 的特殊转场 |
| `warp` | 经过 K 的跃迁转场 |

## 7. 展示顺序

节点内选择：

```text
选项 → result_blocks → 状态/系统提示 → 刷新本节点 choices
```

跨节点选择：

```text
选项 → result_blocks → 场景转场 → 新节点 entry blocks → 新 choices
```

任何阶段都不得让下一组选项提前出现。

## 8. ID 规则

- 节点、entry sequence、choice 和 block ID 必须稳定且唯一。
- ID 不使用时间戳。
- 建议格式：`节点.用途.语义.序号`。
- 修改文本不修改 ID；只有语义实体被替换时才创建新 ID。

## 9. 校验

修改剧情后必须执行严格校验：

```powershell
python backend/scripts/validate_story_v2.py --strict
```

校验器会检查 schema、节点/选项/内容块 ID、目标引用、默认入口和从 A
出发的图可达性。文献、刻字、标题和内心引述继续使用 `narration`；
存在嵌套强调引号的复杂段落使用显式内容块，不在运行时推断。
