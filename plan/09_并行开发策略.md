# Cycle Master — 并行开发策略

> **用途**：识别各开发阶段中可并行执行的任务，提供多人和单人两种场景的最优路径  
> **关联文档**：[00_总览与路线图.md](00_总览与路线图.md) | 各 Phase 详细计划

## 二、Phase 间并行

### 2.1 最大并行窗口：Phase 4 + Phase 5

**触发条件**：Phase 3（API）完成

**为什么可以并行**：
- 两个 Phase 共享同一套 API 层，但调用的端点完全隔离：
  - Phase 4 只用 `/api/game/*` 和 `/api/saves/*`
  - Phase 5 只用 `/api/editor/*`
- 共享同一套 TypeScript 类型定义（[types/index.ts](Phase 1 产出)）
- 共享同一个 Axios 客户端实例
- Pinia Store 完全独立：`gameStore` vs `editorStore`，无任何交叉引用
- Vue 组件树完全独立：`GamePlay.vue` vs `EditorLayout.vue`，不同路由

**唯一共享依赖**：TypeScript 类型文件。Phase 1 产出后即可确定。

**节省**：4 周（串行 8 周 → 并行 4 周）

### 2.2 第二并行窗口：Phase 6 + Phase 7 前半

**触发条件**：Phase 4（播放器）完成

```
Phase 4 完成
    │
    ├── Phase 6 (故事数据) ───── 用播放器验证内容渲染
    ├── Phase 7-动画/转场 ───── 在播放器上加体验层
    ├── Phase 7-音效 ────────── 与动画独立，并行录制/整合
    └── Phase 7-UX/快捷键 ───── 与动画/音效独立
```

**节省**：2-3 周

### 2.3 跨 Phase 前置：Phase 6 数据提前编写

**触发条件**：Phase 1（数据 Schema 确定后）即可开始

Phase 6 的核心工作是**写 JSON 文件**——不依赖任何后端引擎代码或前端 UI 代码。只要在 Phase 1 中确定了数据格式规范（`故事内容格式规范.md`），就可以在 Phase 2-5 的任意时间同步编写。

```
Phase 1 (Schema 确定)
    │
    ├── Phase 2-5 (正常推进)
    │
    └── 同步手写 story_data JSON ── 不阻塞，随时可做
              │
              └── Phase 3 完成后即可用 API 导入验证
```

**节省**：3 周（Phase 6 在 Phase 2-5 期间零工期完成）

## 三、Phase 内任务级并行

### Phase 0：项目骨架（1 周）

```
Day 1-2: 后端项目初始化     ──┬── 并行（独立操作）
Day 3-4: 前端项目初始化       ──┤
                                │
Day 4-5: .editorconfig 等规范   ──┘  共享约定
Day 5:   启动脚本               ──  依赖两端都建好
```

| 任务 A | 任务 B | 共享依赖 |
|--------|--------|---------|
| `backend/` 骨架 + pip install | `frontend/` 骨架 + npm install | 无 |

---

### Phase 1：数据层（2 周）

```
Day 1-3: ┌─ StoryNode/Choice 模型  ──┐
         ├─ Save/PersistentState 模型 ──┤  并行（各自建表）
         ├─ Item/FlagDef 模型       ──┤
         └─ NPC/AttributeDef 模型   ──┘
Day 3-5: Pydantic Schema (game.py + editor.py) ── 依赖模型字段
Day 6-7: 种子数据                    ── 依赖所有模型
Day 8-9: 导入脚本框架                ── 依赖 Schema
Day 10:  TypeScript 类型             ── 依赖 Pydantic Schema 结构
```

| 可并行组 | 内容 | 依赖 |
|---------|------|------|
| 模型组 | 6 个 SQLAlchemy 模型 | 仅依赖 Base |
| Schema 组 | 2 个 Pydantic 文件 | 仅依赖模型字段名 |
| 双端类型 | Python Schema + TS 类型 | 互相参照但不阻塞 |

---

### Phase 2：图引擎（3 周）

```
Day 1-3:   graph.py            ──┬── 三模块零依赖
Day 4-7:   condition_eval.py   ──┤   可同时开发
Day 8-10:  special_router.py   ──┘
Day 11-15: engine.py            ── 依赖以上三模块 + effects.py

贯穿: 单元测试 — 每完成一个模块立即编写
```

| 模块 | 可并行原因 |
|------|-----------|
| `graph.py` | 只做纯 SQL 查询，不管状态 |
| `condition_eval.py` | 只依赖 GameState 数据结构（Phase 1 Schema） |
| `special_router.py` | 只依赖 graph.py 的查询接口 + condition_eval |

`engine.py` 必须等三个模块全部完成，因为它的流程是"调用 graph 查询 → 调用 evaluator 校验 → 调用 router 获取特殊选项 → 调用 effects 执行变更"。

---

### Phase 3：API 集成（2 周）

```
Day 1-4:   game 路由 (/api/game/*)    ──┬── 独立路由文件
Day 5-7:   saves 路由 (/api/saves/*)  ──┤   可并行编写
Day 8-9:   start_new_game             ── 关联两条路由
Day 10-12: 集成测试                    ── 依赖全部路由
Day 13-14: 错误处理/input validation   ── 依赖测试暴露的边界
```

---

### Phase 4：游戏播放器（4 周）— 并行度最高

```
Week 1-2:  GameStore (Pinia)  + game.ts API 层
Week 2-3:  ┌─ TypewriterText.vue     ──┐
           ├─ NarrativePanel.vue      ──┤
           ├─ ChoicePanel.vue         ──┤  6 个叶子组件
           ├─ CycleMap.vue (SVG)       ──┤  可同时开发！
           ├─ StatusBar.vue           ──┤
           └─ SaveLoadPanel.vue       ──┘
Week 3-4:  ┌─ GamePlay.vue (组装)     ── 依赖全部组件
           └─ CycleEndOverlay.vue      ── 独立（纯 CSS 动画 + props）
```

| 组件 | 依赖 | 可并行原因 |
|------|------|-----------|
| TypewriterText | content: string | 纯渲染，无状态依赖 |
| NarrativePanel | TypewriterText | 组合 TypewriterText + SpeakerTag |
| ChoicePanel | choices: ChoiceResult[] | 纯列表渲染 |
| CycleMap | gameState (只读) | 独立 SVG 绘制 |
| StatusBar | gameState (只读) | 只读数据展示 |
| SaveLoadPanel | savesApi | 独立 API 调用 |
| BackgroundLayer | background: string | 纯 CSS 过渡 |
| CycleEndOverlay | cycleEvent | 纯动画组件 |

**关键**：所有 6 个叶子组件只需要知道 **props 的类型定义**（来自 Phase 1 的 `types/index.ts`），互不引用。可以 6 个人同时写 6 个组件，最后在 `GamePlay.vue` 中组装。

---

### Phase 5：可视化编辑器（4 周）— 三栏独立

```
Week 1-2:  EditorStore + editor.ts API 层 + editor 路由
Week 2-4:  ┌─ GraphCanvas (Cytoscape.js) ──┐
           ├─ NodeListPanel                 ──┤  三栏独立
           └─ InspectorPanel                ──┘  共享 EditorStore
Week 4:    EditorLayout 组装 + 条件语法高亮 + 实时预览
```

| 面板 | 核心依赖 | 可并行原因 |
|------|---------|-----------|
| GraphCanvas | Cytoscape.js + EditorStore.nodes | 独立画布操作 |
| NodeListPanel | EditorStore.nodes (只读) | 独立列表渲染 |
| InspectorPanel | EditorStore.selectedNode/selectedChoice | 独立表单编辑 |

**关键**：三个面板通过 `EditorStore` 通信（选中节点 → 属性面板显示；属性面板修改 → 画布更新），但**组件本身不互相引用**。可以 3 个人同时写 3 个面板。

---

### Phase 6：故事数据（3 周）— 天生并行

```
Day 1-4:   导入脚本完善              ──┬── 一人即可
Day 5-18:  ┌─ 8 主节点 JSON           ──┤
           ├─ 2 特殊节点 JSON         ──┤
           ├─ 20 子节点 JSON           ──┤  可 N 人同时写
           ├─ 30 choice 文件          ──┤  互不冲突
           ├─ items/flags/npcs JSON   ──┤
           └─ 数据校验测试             ──┘
Day 19-20: 全量集成 + 游玩测试
```

每个 JSON 文件**完全独立**，30 个节点文件可以由多人并行编写，只要约定好：
- ID 命名规范（不重复）
- `next_node_id` 引用已存在的节点 ID
- `condition` 使用的 flag/item ID 已定义

---

### Phase 7：打磨测试（3 周）— 四个独立工作流

```
Day 1-5:   动画/转场 (CSS/SCSS)     ──┐
Day 6-8:   音效系统                   ──┤  全并行
Day 9-11:  UX 优化/快捷键/设置面板    ──┤  互不阻塞
Day 12-16: 全量测试 (pytest+Playwright)──┘
Day 17-20: Tauri 打包                 ──  依赖全量测试通过
Day 20-21: 发布准备                   ──  依赖打包结果
```

| 工作流 | 依赖 | 可并行原因 |
|--------|------|-----------|
| 动画/转场 | 组件 CSS 类名 | 纯前端样式 |
| 音效 | 音频资源文件 | 设计和编码独立 |
| UX/快捷键 | 组件事件 | 键盘事件 + 设置面板独立组件 |
| 测试 | 全功能稳定 | 可提前写测试用例 |
| Tauri 打包 | 所有代码完成 | 独立配置和构建流程 |

## 四、多人团队最优调度

### 4.1 团队角色（建议 3 人）

| 角色 | 技能栈 | 负责 |
|------|--------|------|
| **后端** | Python/FastAPI/SQL | Phase 0-3 后端 + Phase 5 编辑器 API |
| **前端 A** | Vue 3/TypeScript/SCSS | Phase 4 播放器 |
| **前端 B** | Vue 3/Cytoscape.js | Phase 5 编辑器 |
| **内容/测试** | JSON/写作/QA | Phase 6 手写数据 + Phase 7 测试 |

### 4.2 3 人团队时间线（~12 周）

```
Week 1:  ████████████  Phase 0 (全员一起搭建骨架)
Week 2-3:████████████  Phase 1 (后端建模 + 前端类型 + 内容写 Schema)
Week 4-6:████████████  Phase 2 (后端引擎 + 前端准备 + 内容开始写 JSON)
Week 7-8:████████████  Phase 3 (后端 API + 内容继续 JSON)
         ├──────────────────────────────────────┤
Week 9-12: 后端: Phase 5 编辑器 API
           前端A: Phase 4 播放器开发    ←── 并行！
           前端B: Phase 5 编辑器开发    ←── 并行！
           内容: Phase 6 JSON 收尾
         ├──────────────────────────────────────┤
Week 13-14: 全员: 集成测试 + Phase 7 动画/音效/UX
Week 15-16: 全员: 全量测试 + bug修复 + Tauri打包 + 发布
```

**总计：~16 周（vs 单人 22 周）**

### 4.3 如果再加 1 人（4 人团队，~10 周）

```
Week 1:     Phase 0 (全员)
Week 2-3:   Phase 1 (2人后端建模 + 1人前端类型 + 1人提前写 JSON)
Week 4-5:   Phase 2 (2人引擎并行 + 1人写测试 + 1人继续 JSON)
Week 6-7:   Phase 3 (1人 API + 1人测试 + 2人同时开始 Phase 4/5 原型)
Week 8-10:  Phase 4 + 5 (前端A播放器 + 前端B编辑器 + 后端 editor API + 内容导入)
Week 11-12: Phase 6 + 7 (全员集成打磨 + 发布)
```

## 五、单人开发加速策略

### 5.1 核心思路：砍掉非关键路径

| 策略 | 砍掉内容 | 节省 | 风险 |
|------|---------|------|------|
| **最小可用播放器** | Phase 4 的 CycleMap、SaveLoadPanel、CycleEndOverlay | 1.5 周 | 不影响核心体验 |
| **跳过可视化编辑器** | Phase 5 全部 | 4 周 | 用 VSCode + JSON Schema 代替 |
| **纯 Web 部署** | Phase 7 的 Tauri 打包 | 1 周 | 暂不发桌面版 |
| **仅核心音效** | Phase 7 的 BGM 系统 | 1 周 | 保留打字机声+选项反馈 |
| **提前写 JSON** | Phase 6 在 Phase 1-4 期间零工期完成 | 3 周 | — |

### 5.2 单人最快路径（~15 周）

```
Week 1:    Phase 0     项目骨架
Week 2-3:  Phase 1     数据层 + 开始手写 story_data JSON
Week 4-6:  Phase 2     图引擎（最核心，不压缩）
Week 7-8:  Phase 3     API 集成
Week 9-11: Phase 4     最小播放器（NarrativePanel + ChoicePanel + StatusBar）
                        跳过: CycleMap, SaveLoadPanel, CycleEndOverlay
                        → 期间零碎时间写 JSON
Week 12:   端到端验证   环形 demo 可游玩
Week 13:   Phase 6     导入全部故事数据 + 内容游玩测试
Week 14-15: Phase 7 缩减版:
           - Day 1-2: 基础动画（淡入淡出）
           - Day 3-4: 核心音效（打字机+选项）
           - Day 5-7: 全量测试 + Bug 修复
           - Day 8-9: 快捷键 + 设置面板
           - Day 10:  Web 部署（Netlify/Vercel）
Week 15末:  v1.0.0-web 发布
```

**v1.1.0 后续追加**：
- CycleMap 莫比乌斯 SVG 小地图
- SaveLoadPanel 存档管理
- Phase 5 可视化编辑器
- Tauri 桌面打包

### 5.3 单人日常并行建议

```
上午 (4h)   写代码（引擎/API/组件）
下午 (2h)   写测试 + 修 bug
晚上 (1-2h) 写 JSON 故事数据（不需要写代码技能，纯创作）
```

这样每天有 7-8h 有效产出，3 条线同步推进，无需上下文切换成本（JSON 写作与编码使用不同脑区）。

## 六、并行开发的风险与缓解

| 风险 | 场景 | 缓解 |
|------|------|------|
| **API 接口变更** | Phase 4 和 Phase 5 并行开发时，后端 API 还在调整 | 先确定 Pydantic Schema（Phase 1），前后端以 Schema 为契约。Mock 数据先行开发 |
| **TypeScript 类型不同步** | 多人同时改 types/index.ts | Phase 1 确定后锁定，后续变更走 PR review |
| **JSON ID 冲突** | 多人并行写 story_data JSON | 提前分配 ID 段（如 A 负责 A-D 节点，B 负责 E-H 节点） |
| **组件集成冲突** | 6 个播放器组件并行开发后组装失败 | 每个组件先写单元测试 + Storybook 独立验证，再集成 |
| **条件表达式语法不一致** | 多人写 choice.condition 时格式不同 | Phase 2 完成 condition_eval 后立即发布语法速查卡；Phase 6 导入时 check_syntax() 自动拦截 |

## 七、总结：并行度矩阵

| 阶段 | 最大并行人数 | 可并行任务数 | 节省幅度 |
|------|------------|------------|---------|
| Phase 0 | 2 | 2 (前后端初始化) | 0.5 周 → 0.3 周 |
| Phase 1 | 3 | 3 (模型/Schema/TS类型) | 2 周 → 1.5 周 |
| Phase 2 | 3 | 3 (graph/condition/router) | 3 周 → 1.5 周 |
| Phase 3 | 2 | 2 (game路由/saves路由) | 2 周 → 1.5 周 |
| Phase 4 | **6** | **6 (6个叶子组件)** | 4 周 → 2 周 |
| Phase 5 | **3** | **3 (3个面板)** | 4 周 → 2 周 |
| Phase 6 | **10+** | **30+ (30个JSON文件)** | 3 周 → 1 周 |
| Phase 7 | **4** | **4 (动画/音效/UX/测试)** | 3 周 → 1.5 周 |

**理论极限**：单人 22 周 → 3 人团队 12 周 → 4 人团队 10 周
