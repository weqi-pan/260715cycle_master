# Cycle Master Phase 1–5 残留问题修复与前端重构计划

> **文档版本**：v1.0
> **制定日期**：2026-07-20
> **适用范围**：`plan/01`～`plan/05` 对应的项目骨架、数据层、图引擎、游戏 API、前端播放器
> **当前状态**：执行中（R2～R4 并行收口）
> **执行原则**：先建立可重复验证的基线，再修改数据契约和核心状态流，最后进行 UI 重构与全链路回归。

---

## 一、修复目标

本轮不是在现有页面上继续堆叠补丁，而是完成一次 **Phase 1–5 稳定化重构**，使项目重新达到“可持续开发”的状态。

核心目标：

1. 系统性发现并修复 Phase 1–5 遗留的显性与隐性缺陷。
2. 重建稳定、可测试的剧情播放流程：
   - 节点入场正文；
   - 角色对话；
   - 玩家选择；
   - 选择结果文本；
   - 同节点刷新或跨节点转场；
   - 下一轮选项展示。
3. 所有正文与对话均支持打字机效果：
   - 正文以单段叙事文本形式显示；
   - NPC 对话显示在左侧气泡；
   - 主角对话显示在右侧气泡；
   - 当前文本未播放完毕时不展示下一组选项。
4. 将剧情 JSON 从“节点正文 + 分离的选项过渡文本”重构为明确的内容块序列，消除前后端对展示顺序的猜测。
5. 修复完整循环、半循环、J 捷径、K 跃迁、跨循环遗留、存档恢复等核心机制。
6. 优化前端视觉，形成低饱和、克制、具有岭南民俗与中式恐怖气质的沉浸式界面。
7. 建立隔离的单元、API、E2E 和视觉回归测试，防止修复后再次退化。

### 1.1 本轮完成定义

只有同时满足以下条件，本计划才可标记为完成：

- A→B→C→D→E→F→G→H→A 主路径可完整游玩。
- A 节点内部调查不会错误增加循环数。
- 到达 E、通过 J、回到 A 时的完整/半循环语义明确且测试通过。
- 所有同节点选项的结果文本能够完整播放，随后正确刷新选项。
- 跨节点选项按照“选择结果 → 转场 → 新节点正文/对话 → 新选项”的顺序播放。
- NPC/主角对话左右位置由角色身份决定，不再按数组奇偶交替。
- 存档恢复后的状态与保存前一致，包括节点遗留状态。
- JSON 中不存在未解析的 `{{#if}}`、`{{else}}`、`{{/if}}` 或效果标记泄漏。
- 30 个现有节点均可通过正常游戏路径或明确的特殊路由到达。
- 后端单元测试、API 集成测试、前端类型检查、生产构建和关键 E2E 全部通过。
- 1280×720、1366×768、1920×1080 三种桌面视口可正常使用；窄屏至少不出现内容不可操作或遮挡。

## 二、范围与边界

### 2.1 本轮包含

- Phase 1：项目启动、配置、依赖、路径、开发规范与可复现性。
- Phase 2：数据库模型、Pydantic/TypeScript 契约、故事数据导入与校验。

## 三、当前基线与已知缺陷

以下内容是计划制定时已经确认或高度可疑的缺陷。正式执行时仍需通过自动化测试、API 检查和浏览器复现补充完整缺陷清单。

### 3.1 P0：阻断主流程

| 编号 | 缺陷 | 影响 | 初步修复方向 |
|---|---|---|---|
| P0-01 | A→A 节点内调查被判定为完成一次循环 | 循环数、循环变体和结局条件全部失真 | 循环检测改为明确的拓扑事件或边类型，不以“目标是 A”单独判断 |
| P0-02 | 同节点选择返回的 `transition_text` 被前端立即清空 | 大量调查、拾取和对话结果不可见 | 用统一播放队列处理 `result_blocks`，播放完后再刷新选项 |
| P0-03 | 跨节点选择结果与新节点正文顺序颠倒 | 过渡文本在错误场景显示、打字机重启 | 后端返回明确 Turn 数据，前端使用有限状态机顺序播放 |
| P0-04 | 节点切换时打字机可能由 `watch` 和延迟回调重复启动 | 正文闪回、重头播放、选项提前出现 | 打字机实例单一化，引入取消令牌和队列版本号 |
| P0-05 | 读档请求结果被丢弃，随后重新开始新游戏 | 读档功能名义存在但不可用 | 增加恢复 Frame API，Store 原子应用存档 Frame |
| P0-06 | `persistent_nodes` 未完整保存和恢复 | 跨循环遗留状态读档后丢失 | 存档改为完整 GameState 快照或事务化关联表 |
| P0-07 | `half_cycle_count` 没有写入逻辑 | 半循环条件永远不能自然触发 | 定义 E/J/K 的计数语义并由引擎生成领域事件 |
| P0-08 | JSON 中条件模板没有实现 | 玩家会看到 `{{#if}}` 等原始标记 | 迁移为结构化 `when` 条件，禁止在文本内写控制语法 |
| P0-09 | 部分子节点不可达 | 已写剧情无法游玩 | 建立图完整性验证，补齐明确入口与返回边 |
| P0-10 | K 跃迁效果把 `sanity_max` 直接设置为 `-1` | 属性状态损坏 | 增加 `modify_attr`/`modify_attr_max` 效果并验证上下限 |
| P0-11 | 特殊选项可被构造请求绕过入口条件或当前位置 | 非法跃迁、状态错乱、异常 500 | 后端以当前状态为准重新验证 node、choice 和特殊路由 |

### 3.2 P1：严重体验或数据问题

| 编号 | 缺陷 | 影响 | 初步修复方向 |
|---|---|---|---|

### 3.3 P2：架构、工具和维护问题

| 编号 | 缺陷 | 影响 | 初步修复方向 |
|---|---|---|---|
| P2-01 | 原计划定义的 Item/NPC/Flag/Attribute 数据未进入统一运行时模型 | 名称、规则、上下限被散落硬编码 | 判断实际需求后补齐只读定义仓库，不机械增加无用表 |

| P2-08 | 旧 E2E 测试可能修改共享真实数据库且依赖硬等待 | 测试不可重复、可能污染数据 | 每个测试使用临时数据库、独立浏览器上下文和自动等待 |
| P2-09 | 前端主页面职责过重 | 修改一个时序容易破坏其他功能 | 拆分播放器、正文、对话、选项、场景和面板组件 |
| P2-10 | 依赖版本、应用版本和文档状态不一致 | 环境复现困难 | 统一版本策略、开发依赖与启动命令 |

## 四、关键架构决策

### 4.1 JSON 是唯一故事事实源

修复后应遵守：

```text
data/story_data/v2/*.json
        │
        ├── schema 校验
        ├── 图完整性校验
        ├── 内容模板校验
        └── 原子导入
                ↓
          SQLite 运行时数据库
```

- SQLite 是运行时缓存和存档容器，不是故事内容的最终事实源。
- 编辑器修改必须能够回写 JSON，或导出经过校验的 JSON 补丁。
- 导入前必须验证全部文件；任何一个文件失败时不得清空现有故事数据。
- 故事导入默认不得删除玩家存档。

### 4.2 剧情 JSON v2：使用内容块，不在字符串里写流程

当前 `content + dialogue_lines + choice.transition_text` 无法明确描述展示顺序。v2 改为节点内聚结构，并将选项与其结果内容放在同一节点文件中。

### 4.3 ContentBlock 规范

首版只允许以下块类型：

| 类型 | 用途 | 展示方式 |
|---|---|---|
| `narration` | 场景正文、心理描写、选择结果叙述 | 单段文本区，打字机 |
| `dialogue` | NPC 或主角台词 | 左/右气泡，打字机 |
| `system` | 获得道具、属性变化、线索提示 | 小型系统提示，不混入正文 |

规则：

- `dialogue.speaker_id = "player"` 时固定在右侧。
- 其他 `speaker_id` 根据 NPC 定义显示姓名、头像并固定在左侧。
- 不以数组索引、性别或临时 CSS 判断左右。
- `narration` 不带角色头像，不显示为气泡。
- 效果标记不得写在文本中；`[sanity -3]` 等必须由 `effects` 和 `system` 块表达。
- 文本只允许简单变量插值，例如 `{{cycle_count}}`。
- `{{#if}}`、`{{else}}`、`{{/if}}` 一律禁止；条件必须写在 `when` 字段或独立选择条件中。
- 每个 block 必须有稳定 ID，便于跳过、存档恢复、测试和编辑器定位。

### 4.4 后端返回 Turn，而不是让前端猜测流程

建议将一次选择的返回结构调整为：

```json
{
  "turn_id": "uuid-or-monotonic-id",
  "from_node_id": "C",
  "to_node_id": "C",
  "navigation": "stay",
  "result_blocks": [],
  "next_scene": {
    "node": {},
    "entry_blocks": [],
    "available_choices": []
  },
  "state": {},
  "state_delta": {},
  "events": []
}
```

`navigation` 取值：

- `stay`：节点内互动，播放结果后直接显示同节点刷新后的选项。
- `travel`：播放选择结果后执行场景转场，再播放新节点入场内容。
- `cycle_complete`：完整循环回到 A，插入循环完成演出。
- `shortcut`：J 捷径专用转场。
- `warp`：K 跃迁专用转场。

后端职责：

1. 验证路径 `node_id` 与服务端/请求状态一致。
2. 验证选择确实属于当前节点且当前可用。
3. 解析所有条件和简单变量。
4. 应用效果并返回完整新状态与差异。
5. 决定 `navigation` 和领域事件。
6. 返回已经筛选好的内容块；前端不解释剧情条件。

### 4.5 前端播放器有限状态机

播放器只允许以下状态：

```text
idle
  ↓
typing_narration
  ↓
typing_dialogue
  ↓
awaiting_advance
  ↓
showing_choices
  ↓ 用户选择
submitting_choice
  ↓
playing_result_blocks
  ↓
transitioning（仅 travel/cycle/shortcut/warp）
  ↓
playing_entry_blocks
  ↓
showing_choices
```

关键交互规则：

- 第一次点击当前文本：立即补全当前 block。
- 当前 block 已完整时再次点击：进入下一个 block。
- 播放队列未结束时不得出现选项。
- 选项出现后，点击任一选项立即锁定整组选项。
- 只接受与当前 `turn_id` 匹配的响应；旧响应直接丢弃。
- 新 Turn 到来时取消旧打字机、延迟回调和音频切换。
- 不再通过多个 `watch + setTimeout` 隐式推动剧情。

## 五、前端 UI 重构方向

### 5.1 参考原则

《探灵笔记》的公开界面可作为中式民俗恐怖氛围参考，重点吸收：

- 低照度场景与强暗角；
- 黑、灰褐、暗红、旧金色的克制配色；
- 符纸、印章、旧纸张、香火烟尘等民俗视觉语言；
- HUD 贴边、中心区域尽量留给场景与叙事；
- 关键提示使用朱砂色，超自然事件使用冷灰蓝。

不直接照搬其第三人称对战 HUD。Cycle Master 是文字叙事游戏，信息层级必须服务于阅读和选择。

参考入口：

- [Steam：探灵笔记/拾遗记-1V5](https://store.steampowered.com/app/991780/Notes_of_Soul/?l=schinese)
- [indienova：探灵笔记](https://indienova.com/game/notes-of-soul)


### 5.4 视觉与可用性标准

- 正文最大宽度约 720px，行长控制在中文 28～38 字。
- 正文字号桌面端不低于 18px，行高约 1.8。
- 气泡宽度不超过内容区 72%，同一角色连续对话保持同侧。
- 主角与 NPC 的颜色差异清晰，但避免高饱和聊天软件风格。
- 选项按钮需要有默认、悬停、锁定、提交中、特殊捷径、特殊跃迁状态。
- 所有主要按钮具备键盘焦点和可读的 `aria-label`。
- 动效提供“减少动态效果”开关；打字速度可配置并可一键关闭。
- 背景图加载失败时显示色板背景，不出现破图。
- 状态栏与抽屉不能遮挡当前正文或选择按钮。

## 六、执行阶段

本轮使用 R0～R7 表示修复阶段，避免与原 Phase 编号混淆。

### R0：冻结基线与安全测试环境

**目标**：确保后续每个修改都可复现、可回滚、不会污染真实故事库和存档。

任务：

1. 记录当前 Git 状态、依赖版本、数据库结构和数据统计。
2. 建立缺陷台账：编号、复现步骤、预期、实际、严重度、关联文件和测试。
3. 创建临时 SQLite 测试数据库 fixture，不再让 E2E 修改 `data/cycle_master.db`。
4. 建立只读故事 JSON 校验命令。
5. 为关键 UI 添加稳定 `data-testid` 和语义化选择器。
6. 配置测试失败截图、浏览器 trace 和必要日志。

验收：

- 测试可重复执行且不改变仓库故事数据、真实数据库和存档。
- 已知 P0 缺陷均有失败测试或最小复现脚本。
- 工作区无无关修改。

### R1：剧情 JSON v2 与迁移工具

**目标**：先解决数据无法准确表达展示顺序的问题。

任务：

1. 定义 JSON Schema/Pydantic Schema：SceneSpec、ContentBlock、EntrySequence、StoryChoice、NextAction。
2. 编写 v1→v2 迁移器，保留旧文件备份或生成到新目录，不原地破坏源数据。
3. 将 `transition_text` 迁移到 `result_blocks`。
4. 将 `dialogue_lines` 和正文中的角色台词迁移成 `dialogue` block。
5. 将文本中的效果标记迁移到 `effects + system block`。
6. 将 `{{#if}}` 控制逻辑迁移为结构化 `when` 或互斥 block。
7. 将节点与所属 choices 合并到同一故事文件。
8. 为 30 个节点执行 schema、ID、引用、条件和可达性校验。

验收：

- v2 数据全量通过 schema 校验。
- 不存在重复 block/choice ID。
- 不存在未知条件、未知效果、无效节点引用或未解析控制模板。
- v1 与 v2 的关键剧情文本数量有迁移对账报告。

### R2：引擎与状态模型修复

**目标**：让后端成为剧情流程和游戏规则的唯一裁决者。

任务：

1. 重构 GameState 默认值，全部使用安全的 `default_factory`。
2. 引入 TurnResponse、StateDelta 和领域事件。
3. 修复完整循环与半循环判定。
4. 实现 J 捷径和 K 跃迁的入口、出口、代价及非法请求校验。
5. 拆分 EffectApplier，补齐：
   - add/remove item；
   - 堆叠与去重；
   - set/remove/toggle flag；
   - modify/set attribute；
   - modify attribute max；
   - leave item/danger；
   - UI event。
6. 未知效果必须返回可定位错误，不允许静默忽略。
7. 实现锁定选项、锁定原因、隐藏策略和重复策略。
8. 修复节点可达性和 linked sub node 的实际入口。
9. 为模板变量使用白名单插值，后端返回最终文本。

验收：

- A→A 调查不增加循环数。
- E、J、H→A、K 的计数和事件符合明确规格。
- 30 个节点均可达或在数据中明确标记为非游戏节点。
- 所有效果、条件和特殊路由具备单元测试。
- 引擎测试覆盖核心分支，目标行覆盖率不低于 85%。

### R3：API、数据库与存档修复

**目标**：保证前后端契约稳定、状态可恢复、导入安全。

任务：

1. 统一 API 响应字段和错误结构。
2. 增加当前节点、choice、state/turn 的一致性验证。
3. 实现新游戏、选择、恢复存档的完整 Frame/Turn API。
4. 存档持久化完整 GameState，包括 persistent nodes、选择记录和必要播放器断点。
5. 导入器改为：预校验 → 单事务写入 → 后校验 → 提交。
6. 故事导入与存档表操作解耦。
7. 显式启用 SQLite foreign keys，并决定是否启用 WAL；用测试验证。
8. 为 OpenAPI/Pydantic/TypeScript 建立字段一致性检查。

验收：

- 存档保存后加载，状态深度比较一致。
- 导入无效 JSON 时旧数据库保持不变。
- 非法节点、非法选择、条件不满足和状态冲突返回规范 4xx，不出现 500。
- API 集成测试覆盖主循环、半循环、J/K、存档和遗留状态。

### R4：前端播放状态机与打字机重构

**目标**：彻底修复正文、对话、选择结果和下一节点之间的错乱。

任务：

1. 删除 GamePlay 中分散的打字机定时器和重复推进逻辑。
2. 实现 StoryPlayer 有限状态机和单一播放队列。
3. 实现 TypewriterText：
   - Unicode 字素安全；
   - 标点停顿；
   - 点击补全；
   - 再次点击推进；
   - 组件卸载/Turn 切换取消；
   - 可配置速度和关闭动画。
4. 实现 NarrationBlock、DialogueBlock、SystemBlock。
5. 对话左右由 speaker_id 决定。
6. 实现节点内选择结果播放完后刷新选项。
7. 实现跨节点选择结果播放完后转场，再播放新节点内容。
8. 选择请求期间锁定整组按钮并处理超时、失败和重试。
9. 移除直接拼接不完整 HTML；Markdown 使用受控子集和消毒。

验收：

- 正文、每一条对话、选择结果均逐字出现。
- C/D 连续 NPC 台词始终在左侧，主角台词始终在右侧。
- 快速点击、连续跳过、网络延迟和重复响应不会导致错序。

**目标**：在稳定播放器上完成沉浸式中式恐怖视觉，不用 CSS 掩盖流程问题。

```text
R0 基线/隔离测试
  ↓ Gate 0：P0 均有复现
R1 JSON v2
  ↓ Gate 1：数据全量校验通过

  ↓ Gate 2：引擎单测与图校验通过

  ↓ Gate 3：API 集成测试通过

  ↓ Gate 4：关键交互 E2E 通过

  ↓ Gate 5：多视口视觉审核通过

  ↓ Gate 6：存档/地图/背包 E2E 通过
```

禁止跨 Gate 推进的情况：

- 为了展示新 UI 而跳过 JSON/状态流修复。
- 在真实故事数据库上执行会写入的 E2E。
- 在没有失败测试或稳定复现的情况下修复复杂时序问题。
- 用更多 `setTimeout`、DOM 判断或局部布尔变量修补状态机问题。
- 同时保留 v1/v2 两套长期运行逻辑而没有明确移除日期。

## 九、风险与回滚策略

| 风险 | 应对 |
|---|---|
| JSON v2 迁移损失剧情文本 | v1 只读保留；生成迁移对账报告；逐节点抽样审核 |
| API 改动导致前后端同时不可运行 | 先定义契约测试；按适配层过渡；同一提交内完成端到端字段变更 |
| UI 重构再次引入时序 bug | 状态机先行；组件只渲染状态；关键流程 E2E 作为 Gate |
| E2E 污染真实数据 | 临时数据库、独立 data 目录、测试结束清理 |
| 视觉范围无限扩大 | 本轮只建立设计系统和核心播放器，不承担大规模美术生产 |
| 旧编辑器不兼容 v2 | 先提供只读兼容/导出，再逐步升级编辑能力；不阻塞播放器主流程 |

每个 R 阶段应形成独立、可回滚的提交；禁止把 JSON 全量迁移、引擎重构和 UI 重构混在单个不可审查提交中。
